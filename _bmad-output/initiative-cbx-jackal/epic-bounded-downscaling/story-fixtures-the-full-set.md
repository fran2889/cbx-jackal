# Fixtures: the full set

## Description

Every classification the geometry and report entries assert has a named fixture: all eight orientation values, both TIFF endians, a recognised spread at and beyond 1.35:1, a near-miss below it, a landscape splash page the exemption will misread, and a page scanned sideways carrying no tag. Generated bytes only, so nothing here waits on code.

## Acceptance Criteria

Every fixture is generated by make_fixtures.py, is byte-stable on a second run, and the suite reports zero skips with cjxl, djxl, jxlinfo and magick all on PATH.

## Fixture Requirements

### Orientation Fixtures
- `page_orient_1.jpg` - Normal (0°)
- `page_orient_2.jpg` - Mirrored (flip horizontal)
- `page_orient_3.jpg` - Rotated 180°
- `page_orient_4.jpg` - Mirrored and rotated 180°
- `page_orient_5.jpg` - Mirrored and rotated 270° CW (or 90° CCW)
- `page_orient_6.jpg` - Rotated 90° CW (or 270° CCW) - **display width is the height**
- `page_orient_7.jpg` - Mirrored and rotated 90° CW
- `page_orient_8.jpg` - Rotated 270° CW (or 90° CCW)

All orientation fixtures are 2000x3000 pixels (portrait aspect) so that:
- Orientation 6: display dimensions are 3000x2000 (rotated 90° CW)
- Orientation 1, 2, 3, 4: display dimensions are 2000x3000
- Orientation 5, 7, 8: display dimensions vary based on rotation

### Spread Fixtures
- `spread_exact_1.35.jpg` - Exactly 1.35:1 aspect ratio (e.g., 2000x1481) - **should be exempt**
- `spread_above_1.35.jpg` - Above 1.35:1 (e.g., 2000x1300) - **should be exempt**
- `spread_below_1.35.jpg` - Below 1.35:1 (e.g., 2000x1500) - **should NOT be exempt**

### Edge Case Fixtures
- `landscape_splash.jpg` - Wide page (e.g., 3000x1000) - **the exemption misreads this as a spread**
- `sideways_no_tag.jpg` - Portrait page scanned sideways with no EXIF tag (2000x3000, no orientation) - **should be treated as landscape**

## Implementation Notes

- All fixtures are generated programmatically using ImageMagick for the base images and our EXIF injector for orientation
- Fixtures are byte-stable: running make_fixtures.py twice produces identical bytes
- Both TIFF endians (II and MM) are tested by injecting EXIF with different byte orders
- The `sideways_no_tag.jpg` fixture has no EXIF at all (not even an APP1 segment)
