---
idea: CLI in cbx-jackal that converts CBZ comic archives from JPEG pages to JXL pages, either lossless or at a given quality. Python, no Python imaging libraries, minimal external CLI tools, standalone binary. Output is a CBZ containing .jxl pages.
goal: Pressure-test whether the idea holds up and harden it into something worth building.
status: complete
updated: 2026-10-05T23:31
---

- (lock) No Python imaging libraries. Container handling via Python stdlib only (zipfile).
- (lock) External CLI tools allowed but must be cross-platform and free software, and the count kept minimal.
- (decision) Output is a CBZ whose pages are .jxl. Incompatibility with most comic readers accepted knowingly as a constraint.
- (assumption) cjxl from libjxl can be the sole external encoder, decoding JPEG itself so Python never touches a pixel. Unverified.
- (assumption) 'Standalone binary' is achievable. Contradiction not yet resolved: a frozen Python binary still leaves cjxl as an external runtime dependency.
- (crack) Choosing JXL-in-CBZ removed the only justification for lossless mode: bit-exactness against the decoded JPEG is unobservable, and lossless JXL of an already-lossy source has no guaranteed size win and often regresses on photographic pages.
- (lock) Lossless mode is justified by SIZE, not reversibility. Measured with libjxl 0.11.1: comic-like page 22065->11463 bytes (48% smaller); photo-like page 122465->98907 (19.2% smaller). Both lossless.
- (lock) JXL roundtrip is bit-exact on pixels: two independent JXL encodes decoded via libjxl give 0 differing pixels. Any JPEG-vs-JXL pixel difference is JPEG DECODER disagreement (chroma upsampling + IDCT rounding), not a JXL loss.
- (kill) Claim that the original JPEG can be reconstructed by reverse conversion. Disproven: two JPEGs differing only by an inserted 22-byte COM marker decode to 0 differing pixels, so pixel data cannot determine the original file. Quantization is lossy integer rounding; JPEG structure/metadata is absent from JXL.
- (crack) My earlier assertion that lossless JXL regresses in size on photographic pages is WRONG; measurement shows ~19% saving there. Retracted.
- (note) libjxl semantics confirmed from cjxl --help: -q 100 = mathematically lossless, 68..96 recommended, roughly matches libjpeg quality. For JPEG input, -d 0 (lossless) is already the default.
- (lock) Default is lossless. Bare invocation must never destroy quality. cjxl already defaults to -d 0 for JPEG input, so the tool matches that.
- (lock) Packaging: v1 ships as a Python entry point with a preflight dependency check for cjxl. Do NOT bundle binaries. Cross-platform from day one, zero release engineering.
- (note) Bundling ruled out on Ines Duarte's Linux ABI-conflict argument (two libjxl copies, global decoder handler registration, silent corruption). Sizes measured anyway: cjxl 0.3 MB, libjxl proper 3.6 MB, full native runtime 10.1 MB.
- (lock) Output naming: <name>.jxl.cbz beside the input (e.g. MyComic.cbz -> MyComic.jxl.cbz). Never in-place; refuse to overwrite unless forced.
- (lock) Page order = source ZIP stored entry order, verbatim. No natural-sort, no renumbering. Principle of least surprise: readers apply their own filename sort; we must never silently reorder a book.
- (lock) Accepted by silence: pages = JPEG extensions only (.jpg/.jpeg, case-insensitive); all other entries pass through byte-for-byte at original position (ComicInfo.xml, readme.txt, nested dirs, __MACOSX, PNG/WebP, already-.jxl); ZIP entries STORED not deflated (JXL already entropy-coded, deflate gains <1%).
- (lock) Concurrency: NOT needed in v1. Measured lossless encode at A4/300dpi: flat comic art 0.08s/page, detail-heavy 0.16s/page -> a 200-page book converts serially in ~16-32s. Process pool is premature complexity.
- (decision) No --effort flag in v1. cjxl effort 7 measured identical in speed AND size to effort 3, while effort 9 costs 10-40x the time for +0.5-3.4% size. Effort 7 is the free default.
- (lock) Failure contract collapses to ONE rule: run cjxl on every JPEG-extension entry; on success write <name>.jxl, on failure copy the original bytes verbatim. Corrupt JPEG is not a special case, just a failed conversion. Everything non-JPEG copied verbatim.
- (lock) Exit code: non-zero only if a JPEG entry FAILED to convert. Non-JPEG pass-throughs (ComicInfo.xml, readme.txt) are normal and must not make the run look failed. One line per failure + '199/200 converted, 1 failed' summary.
- (lock) Output is atomic: build to temp file in destination dir, then rename. A failed run leaves NO output file, never a partial book. --strict aborts on first conversion failure. --dry-run reports plan and sizes, writes nothing.
- (lock) ComicInfo.xml needs NO rewriting: entry count never changes and pages are never renumbered, so <Pages Count> stays correct.
- (note) Verified against libjxl 0.11.1: cjxl exits 1 with no output on truncated and garbage JPEGs (reliable corruption oracle, no silent padding). cjxl sniffs CONTENT not extension - a PNG named .jpg converts fine and the .jxl rename stays correct. cjxl prints 'Implicit-default for JPEG is lossless-transcoding' - adopt libjxl's term 'lossless transcoding'.
- (kill) RETRACTS the earlier 'kill' on JPEG reversibility. jxlinfo reports 'JPEG bitstream reconstruction data available' for -d 0/-q 100 output, and 'djxl x.jxl out.jpg' reproduces the source JPEG BYTE-IDENTICALLY (22065 bytes, sha dbfc0ee1...). My pixels-can't-determine-bytes argument was sound but incomplete: the JXL carries extra reconstruction data, so it is not pixels-only.
- (lock) Lossless transcoding is reversible: -q 100 output embeds JPEG bitstream reconstruction data, so djxl recovers the exact original JPEG. Verified byte-identical. This makes lossless the strongest mode on both size AND fidelity.
- (lock) Reversibility exists ONLY in lossless mode. -q N<100 drops reconstruction data and adds a generation of loss permanently.
- (crack) IMPLEMENTATION TRAP: 'cjxl -q 90' on JPEG input FAILS with 'Must not set quality below 100 in combination with --lossless_jpeg=1, which is set by default.' Any --quality below 100 must also pass --lossless_jpeg=0. Would have broken every lossy run.
- (note) On the test page lossless (11463 B) BEATS lossy -q 95 (14988 B) and ties lossy -q 90 (11995 B) - so lossless is simultaneously smallest-tier, lossless and reversible. Reinforces lossless-as-default decisively.
- (crack) OPEN: jxlinfo shows NO density stored in the JXL (source 150/300/600 dpi all round-trip to 72/undefined via PNG). Pixel dimensions are preserved (2480x3508). Comic readers size pages by physical DPI, so page rendering size may be wrong. Needs verification against a JXL-aware reader.
